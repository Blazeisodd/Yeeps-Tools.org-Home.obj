# Yeeps-Tools.org-Home.obj

A Wavefront OBJ export of a loaded Yeeps room (nexus/hub), generated by the
`YeepsMapLoaderV2` Unity Editor tool. This repo holds just the 3D export —
not the Unity project, not the loader script, not the game's own assets.

## Files in this repo

- `YeepsMap.obj` — the geometry. **Tracked with Git LFS** (see `.gitattributes`
  — `*.obj filter=lfs`). Large (~110MB uncompressed); a plain `git clone`
  without LFS installed will only give you a tiny pointer file instead of
  the real mesh.
- `YeepsMap.mtl` — material definitions, referenced by `YeepsMap.obj` via
  `mtllib YeepsMap.mtl`. One `newmtl` per distinct material actually used in
  the export (~120+ entries), each with a flat `Kd` colour and, where the
  source material has a texture, a `map_Kd` line pointing into
  `YeepsMap_textures/`.
- `YeepsMap_textures/` — every texture referenced by the `.mtl`, as
  `tex_0.png`, `tex_1.png`, etc. Must stay in this exact relative path next
  to the `.obj`/`.mtl` — the `map_Kd` lines use relative paths
  (`YeepsMap_textures/tex_N.ext`), not absolute ones.
- `YeepsMap.zip` — the same OBJ + MTL + textures, pre-zipped as a single
  download-and-go bundle (this is literally what `YeepsMapLoaderV2`'s
  "Download OBJ (.zip, no Blender needed)" button produces).

## How to open it

1. **Clone with Git LFS available** (`git lfs install` once per machine,
   then `git clone` normally — or `git lfs pull` if you already cloned
   without it and got a pointer stub instead of the real `.obj`).
2. Keep `YeepsMap.obj`, `YeepsMap.mtl`, and `YeepsMap_textures/` together in
   the same folder — don't move the `.obj` without the other two, textures
   will silently fail to resolve.
3. **Blender**: File → Import → Wavefront (.obj) → select `YeepsMap.obj`.
   Materials and textures load automatically.
4. **Unity / other 3D tools**: same idea — import `YeepsMap.obj` from a
   location where `YeepsMap.mtl` and `YeepsMap_textures/` are siblings.
5. Alternatively, just unzip `YeepsMap.zip` — it already contains all three
   with the correct relative layout.

## Coordinate system note

The export mirrors on X and reverses triangle winding to convert Unity's
left-handed Y-up into OBJ/Blender's right-handed Y-up. If you re-export a
newer version from `YeepsMapLoaderV2` and something looks mirrored/inside-out
in a different tool, that tool likely expects a different handedness —
that's a property of the exporter (`ExportObj` in `YeepsMapLoaderV2.cs`),
not a bug in this specific file.

## Where this came from

Generated by `Assets/Scripts/Editor/YeepsMapLoaderV2.cs` in a separate,
private Unity project (not in this repo). That script:
- Loads a room's block layout from `spam_blocks.csv` (itself fetched from
  the Yeeps game API via a companion Python script, `read_map.py`)
- Places each block's real prefab at its correct grid position/rotation/size
- Resolves colours from the game's own palette atlas + each block's SPAM
  paint colour (see the script's header comment for the full colour model)
- Exports the result to OBJ+MTL+textures via `ExportObjZip()`

If you need to regenerate this export (new room, updated block placement,
etc.), that has to happen from inside that Unity project — this repo is
just the output artifact, not a place to edit source.
